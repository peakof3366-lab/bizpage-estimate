앞선 검토(1라운드)에 대한 반박입니다. 원문을 다시 확인한 결과 **네 건은 사실과 다르고,
두 건은 이 서비스 구조상 해로운 제안**입니다. 아래 근거를 읽고 **입장을 유지할지 철회할지
각각 명시**한 뒤, 1라운드에서 답하지 않은 핵심 질문에 답해 주세요.

═══════════════════════════════════════════════════════════════════════
## A. 사실 확인 — 당신의 지적 중 원문과 다른 것

### A-1. "문의 관리와 견적 관리를 통합하라" → 반대합니다
두 장은 **서로 다른 화면**입니다(관리자 사이드바의 별개 메뉴). 그리고 상태값이 다른 것은
실수가 아니라 의도입니다. 원문에 이미 그 이유가 적혀 있습니다:

> "문의 관리와 상태 이름이 다릅니다 — 이쪽은 영업 단계를 나타냅니다."

- 문의 상태: 신규 / 확인 / 처리중 / 완료  ← **처리 진행도**
- 견적 상태: 신규 / 상담중 / 계약완료 / 종료 ← **영업 단계**

두 화면을 한 장으로 합치면 상태 8개가 한 자리에 섞입니다. 통합이 여전히 옳다고
보신다면, **상태 8개를 어떻게 헷갈리지 않게 배치할지 구체적인 안**을 제시하세요.
못 하시겠으면 철회해 주세요.

### A-2. "가입코드 용어가 '코드'·'가입 코드'로 섞여 있다" → 원문에 없습니다
당신이 인용한 문장 **"당신의 코드가 외부로 누설되지 않도록 하세요"는 이 문서에 존재하지
않습니다.** 원문 전체에서 해당 개념은 `가입코드` 한 표기뿐이고, 실제 문장은
"팀 공용으로 하나입니다. 외부에 알려주지 마세요." 입니다.
→ 인용을 지어내지 마세요. 철회하거나, **실제로 섞여 있는 다른 용어**를 원문에서 찾아
   제시하세요(있다면 그게 훨씬 유용합니다).

### A-3. "'사장님께 재설정을 요청하세요'를 추가하라" → 이미 있습니다
원문 1장:
> "비밀번호를 5번 틀리면 15분 잠깁니다. **잠겼으면 기다리거나 사장님께 재설정을
>  요청하세요.**"
→ 철회하거나, 이 문장이 **왜 충분하지 않은지**를 말하세요.

### A-4. "비밀번호 분실 방침이 빠져 있다" → 절반만 맞습니다 (이건 유효한 지적)
12장(사장님 장)에는 있습니다:
> "같은 화면에서 비번 재설정을 누르면 잠금도 함께 풀립니다."
하지만 **1장(직원이 읽는 곳)에는 '비밀번호를 잊었을 때 무엇을 해야 하는지'가 없습니다.**
잠긴 경우만 있고 잊은 경우가 없습니다. 이건 채우겠습니다.
→ 이처럼 **"정보는 문서에 있는데, 그게 필요한 사람이 읽는 장에는 없는"** 항목이
   더 있는지 찾아 주세요. 장 번호와 함께 구체적으로.

═══════════════════════════════════════════════════════════════════════
## B. 구조상 해로운 제안

### B-1. "계정 만들기 3단계를 표로 바꿔라"
그 세 항목은 **시간 순서**입니다(코드 받기 → 신청 → 승인 대기). 표는 순서가 아니라
비교를 나타내는 도구입니다. 여전히 표가 낫다고 보시면 이유를 대세요.

### B-2. "각 장 첫머리에 요약을 넣어라"
3·4·5·6장은 **이미** 첫 문장이 그 역할을 합니다(예: 6장 "목적지별 추천 코스와 추천
콘텐츠(방식 A·B)를 고치는 곳입니다"). 없는 장은 7장·8장뿐입니다.
→ 전체에 넣으라는 제안은 중복을 만듭니다. **7·8장에 넣을 요약 문장을 직접 써 주세요.**

═══════════════════════════════════════════════════════════════════════
## C. 1라운드에서 답하지 않은 질문 — 여기가 본론입니다

가장 중요하다고 표시했던 질문에 당신은 일반론으로만 답했습니다. 다시 묻습니다.
**반드시 원문 문장을 인용하고, 고쳐 쓴 문장을 함께 제시**하세요.

### C-1. 첫날 경로
직원 3명이 **오늘 처음** 로그인합니다. 12개 장을 다 읽을 사람은 없습니다.
- 첫날 반드시 읽어야 하는 것은 몇 장 몇 절입니까? (목록으로)
- 그것을 문서 어디에 어떻게 배치해야 합니까? (새 장을 만들지, 머리말을 고칠지)
- 나머지 장은 "필요할 때 찾아보는 것"임을 어떻게 알려야 합니까?

### C-2. 눈이 미끄러지는 구간 — 구체적으로 3곳
문단이 뭉쳐 있거나 한 문장이 너무 긴 곳을 **원문에서 3곳 인용**하고, 각각 어떻게
쪼갤지 고쳐 쓴 문장을 제시하세요. "긴 문장을 나누세요" 같은 답은 받지 않습니다.

### C-3. "고장인가, 원래 그런 건가"
비개발자가 첫 주에 이 판단을 못 해서 막힐 지점을 **문서에 답이 없는 것만** 고르세요.
아래는 **이미 문서에 있으므로 다시 제안하지 마세요**:
- 승인 전 로그인 안 되는 것 / 로그인 12시간 만료 / 안 보이는 메뉴가 있는 것 /
  견적 링크가 "확인 필요"로 걸리는 것 / 배지에 ? 가 뜨는 것 /
  가져온 코스에 옛 목적지 이름이 남는 것 / 저장했는데 숫자가 그대로인 것

### C-4. 인쇄본
이 문서는 인쇄해서 책상에 두고 보는 용도로도 쓰입니다(목차·버튼은 인쇄 시 숨겨집니다).
화면으로 읽을 때와 종이로 볼 때 **무엇이 달라져야 합니까?** 구체적으로.

═══════════════════════════════════════════════════════════════════════
## 답변 규칙
- A-1 ~ B-2 각각에 대해 **유지 / 철회 / 수정**을 첫 줄에 명시하세요.
- C 항목은 **인용 → 문제 → 고쳐 쓴 문장** 3단으로 답하세요.
- 원문에 없는 문장을 인용하지 마세요. 확실하지 않으면 "원문에서 확인 못 함"이라고 쓰세요.
