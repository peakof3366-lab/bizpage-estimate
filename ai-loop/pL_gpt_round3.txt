1. **[c "확인함"의 기준환율 재설정]** / `api/rates.js`, `rateDate` 변경 시 / "확인함" 버튼 누름 / 기준환율이 오늘자로 리셋되어 기존 환율 보정이 사라집니다 / 높음  
   - 설명: 코드 B에서는 `rateDate`가 변동될 때마다 기준환율(`rate_fx_baseline`)을 오늘의 환율로 재설정합니다. "확인함" 버튼도 해당 메커니즘으로 작동하여 환율 기준점이 초기화됩니다. 사용자가 "가격 그대로"를 의도한 경우, 환율 보정 누적이 사라질 수 있어 가격이 의도치 않게 변동될 가능성이 있습니다.

2. **[동시 편집의 문제]** / `api/rates.js` / 두 명의 사용자가 같은 목적지의 다른 항목을 동시에 수정 / 한 명의 수정 내용이 조용히 사라질 수 있음 / 높음  
   - 설명: 코드 B의 요율 저장 로직은 `on conflict` 절에서 변경사항을 병합하지만, 동시에 다른 사람이 수정한 내용이 덮어쓰여질 수 있는 위험이 있습니다. 여러 팀원이 동시에 같은 목적지의 항목을 수정할 경우 특히 문제가 발생할 수 있습니다.

3. **[클램프된 상태 지속]** / `script.js getFxAdjust` / 특정 환율 변동이 ±30% 이상 지속 / 환율 보정이 ±30%로 고정되고 경고나 알림 없음 / 중간  
   - 설명: 환율 보정은 ±30%로 클램프됩니다. 코드 C의 `adminGetFxDrift` 함수는 변동 배지를 나타내지만, 클램프상태가 장기화될 경우 시스템 내 별도의 경고가 없습니다. 클램프된 상태가 지속되면 장기적으로 원가와 큰 차이가 날 수 있습니다.

4. **[요율 오버라이드 캐시 문제]** / `admin.html` `rateOverridesCache` / 요율 데이터 변경 시 캐시 미갱신 / 관리자 화면과 실시간 상태 불일치 가능성 / 추정  
   - 설명: 관리자가 데이터.js의 정적값 대신 오버라이드를 하여 적용 중인 값을 화면에 보여주도록 설계된 것처럼 보입니다. 캐시가 실시간으로 갱신되지 않는 경우, 특히 `rate_overrides` 테이블에서 변경된 값이 아닐 경우, 관리자 화면과 실제 적용 상태 간에 불일치가 생길 수 있습니다.

5. **[환율 변동 경계값]** / `admin.html adminGetFxDrift` / fxRatesCache의 값 변동 시 / 사용자에게 명확히 드러나지 않음 / 추정  
   - 설명: `fxRatesCache`에서 반환된 환율 변동이 `FX_DRIFT_THRESHOLD_PCT` 이상인 경우 경고 표시가 가능합니다. 하지만 이 경고가 충분히 사용자에게 명확히 전달되지 않을 수 있습니다. 추가적인 UI 개선이 필요할 수 있습니다.

각각의 사항은 해당하는 코드 라인에서 명확히 설명되거나 암시되고 있으며, 일부는 시스템의 설계에 따라 은연중에 존재하는 잠재적 문제로 파악됩니다.
