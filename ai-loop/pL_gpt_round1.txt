[1] 인원 구간별 할인 계산 오류 가능성
- 위치: 코드 1, 함수 `tieredTotal` (라인 10~15)
- 재현 조건: 특정 인원 수 (e.g., 30명)에서 해당하는 구간의 최댓값이 변경된 경우
- 결과: 구간 경계 변경으로 인해 예상과 다른 할인 금액이 적용되어 총액이 잘못 계산될 수 있음.
- 확신도: 중간

[2] 리드타임 계산 시 날짜 계산 오류
- 위치: 코드 1, 함수 `getLeadTimeFactor` (라인 28)
- 재현 조건: 시간대 간의 차이로 인해 오늘 날짜의 리드타임이 틀리게 계산될 수 있음
- 결과: 잘못된 리드타임 계수가 적용되어 가격 계산에 오류가 발생
- 확신도: 중간

[3] 클라이언트 계산 금액을 서버에서 검증하지 않음
- 위치: 클라이언트 측 함수 전반 (코드에서 특정 라인을 명시하기 어려움)
- 재현 조건: 고객이 조작할 수 있는 클라이언트 측 계산된 금액을 조작 (F12 개발자 도구 이용)
- 결과: 고객이 조작하여 낮은 금액으로 견적이 저장될 수 있음
- 확신도: 높음

[4] PEAK_CALENDAR의 해넘이 처리 오류 가능성
- 위치: 코드 1, 함수 `getPeakInfo` (라인 91~104)
- 재현 조건: `from`과 `to`의 값이 연말연시와 같은 해넘이 구간에서 포함 여부가 틀릴 수 있음
- 결과: 피크 시즌이 정확히 적용되지 않아 가격이 과대 또는 과소 책정될 수 있음
- 확신도: 중간

[5] 비즈니스 좌석 인원 계산 오류 가능성
- 위치: 코드 2, 함수 `getBreakdownData` (라인 56~79)
- 재현 조건: `bizCount` 및 `participants`의 입력값이 실수일 경우
- 결과: 혼합 좌석 배율이 잘못 계산되어 항공 비용이 잘못 책정될 수 있음
- 확신도: 중간

[6] 가정된 연호·음력 근사 데이터 유지 문제
- 위치: 코드 1, `PEAK_CALENDAR` 내 설정 (라인 50~71)
- 재현 조건: 설·추석 등의 날짜가 해마다 변함에 따라 잘못된 시기에 과다 비용이 책정
- 결과: 잘못된 가정으로 고객에게 과다 또는 과소 청구될 수 있음
- 확신도: 높음
